# フォームの回答 1 に記録する版

今回使うGASは **Code-form-history.gs** です。以前の Code-with-history.gs は別シート「操作ログ」方式なので、今回はこちらを使わないでください。

1. GASの現在のコードをバックアップします。
2. 新APIのコードを Code-form-history.gs に置き換えます。同じプロジェクト内の別ファイルに doGet / doPost / updateWeight / updateLocation / registerFilament / jsonResponse が重複していないか確認します。
3. 旧Googleフォームを使い続ける場合、旧 onFormSubmit とそのトリガーは残してください。本ファイルには含まれません。
4. GASの「デプロイ」→「デプロイを管理」→対象の鉛筆マーク→バージョン「新バージョン」→デプロイで、現在のURLが指す版を更新します。コードを保存するだけでは公開版は更新されません。
5. 新窓口 portal-preview/index.html も今回のファイルに置き換えて公開します。旧QRreader/index.htmlは変更しません。
6. 確認待ちになっている物品は、現在の台帳値と過去の更新結果を確認してください。過去に履歴が残らなかった更新は今回自動で作り直しません。確認後、画面の確認済みボタンで再開します。

## 記録内容

既存の「フォームの回答 1」にA〜Lの12列で追記します。シート名は半角スペースと半角数字を含むこの名前です。列順が画像・旧GASと異なる場合は更新を停止します。新しいシート・列は作成しません。

タイムスタンプ／用途／管理番号／重量／担当／色／母材／サブカテゴリ／メーカー／保管場所／本数／備考。
旧フォームと同様に、使用・移動時のメーカーなどの未入力項目は空欄とします。移動時の重量も空欄です。
備考には「新窓口」、処理ID、処理中・完了・要確認などの状態、変更前後の値を保存します。通常のGoogleフォーム送信を装うものではなく、新窓口からの記録と区別できます。

フォーム回答シートへのGASからの追記だけでは旧 onFormSubmit は実行されません。そのため新API内で台帳と履歴の両方を更新します。既存のGoogleフォームそのものの回答数には加算されません。

履歴の追記ができなければ台帳更新には進みません。シート間の一括トランザクションではないため途中停止時は備考の「処理中」「要確認」と台帳を確認してください。自動再送はしません。
通常フォーム送信との行番号競合を避けて追記しますが、旧GASや手動編集との台帳同時更新を完全に排他制御するものではありません。

## アプリ登録

旧アプリのscopeは /QRreader/ 全体です。この下の portal-preview/ は旧アプリの範囲内にあるため、別のidを設定してもインストール案内が抑制される場合があります。旧アプリの削除や範囲変更は行っていません。
旧アプリを維持するため、新窓口を別リポジトリの /filament-portal/ などに配置する版を filament-portal.zip に用意しました。ZIP内フォルダの中身を新リポジトリの直下に置いてGitHub Pagesで公開してください。リポジトリの作成・公開は未実施です。
同じホストの別パスは範囲の包含関係を解消できますが、端末による登録可否は実機確認が必要です。完全なアプリ分離が必要なら別ホストで公開します。

## 確認

模擬シートで重量0g、場所変更時ID固定、12列への追記、変更前後・処理状態、入力不備、シート不存在、履歴／台帳の書込失敗を確認。ブラウザでは新APIの版確認、旧版時にPOSTを送らないこと、正常保存、通信失敗時の確認待ちを検証。実台帳への書込み・GASの再デプロイは行っていません。
